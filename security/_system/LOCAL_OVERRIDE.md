# 本機執行的覆寫規則（優先於上文）

本次為**本機草稿產製**，不是發布。上文的發布流程**全部不執行**。

1. **寫到 `security/_drafts/Brief_{{DATE}}.md`**，不要寫進 `security/briefs/`。
2. **不要執行 `rebuild-manifest.py`。**
3. **不要 git add、不要 commit、不要 push。** 這份稿子要先給人看過才會發布。
4. 歷史比對照舊——讀 `security/briefs/` 內既有晨報（那是已發布的）；
   另外也看一下 `security/_drafts/` 內有無尚未發布的近日草稿，避免與未發布稿重複。
5. 今天的日期是 **{{DATE}}**（台灣時間），直接用，不必再自行推算。


## 無人值守執行（最重要）

本次由 Windows 工作排程器於清晨自動觸發，**沒有人在旁邊**。標準輸入已關閉，
任何提問都不會有人回答，等待只會讓整輪逾時失敗。因此：

- **不得詢問使用者、不得等待確認、不得徵求同意。** 遇到判斷分歧，
  選一個合理作法逕行完成，並在草稿末尾以一行註記說明所作的取捨。
- **不得以「回報現況」代替產製。** 本次任務唯一的成功定義是草稿檔案被寫出來。
  輸出說明、盤點清單、問題診斷或待辦建議，都**不算**完成，也不要作為結束的理由。
- **忽略 `_drafts/` 內的 `.run-*.lock`。** 該鎖檔是啟動本次執行的包裝腳本自己建立的，
  記錄的是它的行程編號，並非前次殘留。不要檢查、不要刪除、不要因它而停止。
- **不要自行判斷「今天是否已經跑過」。** 該判斷已由包裝腳本在呼叫你之前完成。
  你被叫起來，就代表今天確實還沒產製。
- 若某個來源取不到、某項資料查不到，**照既有規範標註後繼續**，
  不要因單一環節受阻而中止整份晨報。

其餘規範一律照上文執行，**不因為是草稿而放寬**。

草稿會由人過目後，以 `python security/_system/publish.py {{DATE}}` 發布。
該腳本會檢查固定欄位、來源等級、待查核、佔位字樣與文體，
所以這些項目請一次做對，不要留給發布時再修。
