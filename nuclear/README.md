# 核能晨報 · Nuclear Daily Brief

每日產出一份核能晨報，**依規範屬性分節**而非地理分區：核子安全（針對意外與失效）、
核子保安（針對惡意行為者）、核子保防（針對國家移作他用）。

網站：https://geostrategist.github.io/daily-brief/nuclear/

---

## 這是什麼

母站「實踐國企晨報」的子站，沿用同一套已驗證的架構：沒有後端的靜態網站，
每天由 Claude Code 排程 agent 巡檢固定來源、比對前 21 份晨報、只寫變化，
產出一份 Markdown 檔並推上 GitHub Pages。

**為什麼另開子站而非併入母站主題七**：母站七大主題共用一份晨報，核能被壓縮到每日一至兩則。
本站不受此限，可寫到機組編號、規範條號與單位的層級。
母站主題七自本站上線後改為只寫當日核能最重大的一件事，避免兩邊重複。

**為什麼依規範屬性分節**：核子安全、核子保安、核子保防是**三個不同的規範體系**——
判準來源分別為安全評估、國家威脅評估（DBT）與保防協定，法律地位互不增減
（IAEA NSS 25-G §1.2）。三者在中文公共討論中長期混用，「核安」一詞經常同時指涉三件事。
依此分節，讀者每天看見同一組區分，**區分本身即是本站的價值**。
地理分區則做不到這件事——同一個國家的新聞會橫跨三個規範體系。

## 目錄結構

```
index.html              單檔前端，由母站 index.html 衍生
manifest.json           PWA 設定（圖示指向 ../icons/）
sw.js                   Service Worker，快取名稱與母站分離
briefs/
  manifest.json         日期索引，新的在最前面
  Brief_YYYYMMDD.md     每日晨報
_system/
  TOPICS.md             八個欄位的設定 — 改這裡就改變隔日版面與巡檢範圍
  SOURCES.md            固定巡檢網址清單（18 個，逐一實測過）
  EDITORIAL.md          編輯規範 — 決定怎麼寫
  REFERENCE.md          規範編號、三者之區分、研究缺口、台灣現況基準
  DAILY_PROMPT.md       排程 agent 的每日指令原文
  rebuild-manifest.py   依 briefs/ 內實際檔案重建索引
```

五份 `_system/` 設定檔是這個專案的核心。程式碼幾乎不必再動，日常調整都在這些檔案裡。

## 八個固定欄位

| 順序 | 欄位 | 性質 |
|---|---|---|
| 1 | 機組狀態速覽 | 表格。本日有異動者加上台灣全部機組 |
| 2 | 核能相關動態 | 產業與政策面 |
| 3 | **核子安全**（safety） | 針對意外與失效 |
| 4 | **核子保安**（security） | 針對惡意行為者 |
| 5 | **核子保防**（safeguards） | 針對國家移作他用 |
| 6 | 未來事件行事曆 | 表格。只列今日之後的確定日期 |
| 7 | 建議研究與寫作行動 | 四層：今天要做／本週要追／本月觀察／僅供背景 |
| 8 | 應持續追蹤議題 | 表格。逐日承接更新 |

**第 3 至 5 節每日固定出現**，無實質內容者寫一則巡檢基線，不整節略去。
「今日保防無事」本身即為資訊——保防的動作以年為單位（協定簽署、年度申報、理事會報告），
數日甚至數週無事屬正常。前端為三節各配一色並在摘要下方附圖例。

## 三者的區分

| | 核子安全 safety | 核子保安 security | 核子保防 safeguards |
|---|---|---|---|
| 針對 | 意外與失效 | 惡意行為者 | 國家移作他用 |
| 判準來源 | 安全評估 | **國家威脅評估（DBT）** | **保防協定** |
| 規範體系 | IAEA 安全標準（GSR／SSR／SSG） | IAEA 核子保安系列（NSS） | NPT／INFCIRC/153／540 |

法律地位上保安與保防互不增減。**可觀察的設計差異**比目的宣示有力：
保安之物料平衡區較保防者更小、更貼近製程（NSS 25-G §4.13–4.14、§4.17）。

完整對照與規範編號見 `_system/REFERENCE.md`。

## 每日流程

見 `_system/DAILY_PROMPT.md`。摘要如下：

1. 讀 `TOPICS.md`、`SOURCES.md`、`EDITORIAL.md`、`REFERENCE.md`
2. 逐一 WebFetch 18 個固定來源，取得失敗者記錄於當日晨報，不靜默略過
3. 每則依主要意義分節（產業／安全／保安／保防）
4. 回溯比對近 21 份晨報，只寫新增與變化
5. 產出 `nuclear/briefs/Brief_YYYYMMDD.md`
6. `python nuclear/_system/rebuild-manifest.py`
7. commit 並 push，GitHub Pages 自動發布

**排程**：每日早上八點。母站晨報為七點，兩者錯開以免同時 git push。

## 這個領域特有的坑

架構沿用母站，但核能報導有幾類母站不會遇到的錯誤，規範中已各有對應條文：

**一、機組指涉不清**（`EDITORIAL.md` 第四節）。同一電廠常有多部機組，狀態各不相同。
「柏崎刈羽核電廠重啟」是無效資訊，「柏崎刈羽 6 號機重啟審查通過」才是。
併網、商轉、臨界、重啟審查通過、地方同意，這些詞的時間可差數年，混用即為錯誤。

**二、單位與數量級**（第五節）。發電容量的 MWe 與 MWt 可差三倍；日文的「万kW」
經英文摘要常掉一個數量級。**創刊日就遇到一次**：島根 2 號機的「82.0 万kW」
（＝820 MWe）被英文途徑誤讀為 82.0 MW，回查日文原文才攔下。鈾的磅 U3O8、
噸鈾（tU）、SWU 三種單位也不可互換。

**三、立場**（第六節）。核能是台灣高度政治化的議題。本報只報事實與其後果，不倡議。
不用褒貶性形容詞描述核能本身；擁核與反核的主張一律以引述處理；
判讀可以有判斷，但判斷須指向可觀察的後果，不指向價值評價。
產業協會（nucleareurope、NEI）與反核團體適用同一套來源等級規則，不因立場方向而寬嚴不一。

**四、規範編號**（第十五節）。IAEA 編號改版頻繁——NS-R-1、NS-R-3、GS-R-3、WS-R-5 均已作廢，
分別對應 SSR-2/1、SSR-1、GSR Part 2、GSR Part 6。原能會已於 2023-09-27 改組為核安會。
**編號一律查 `REFERENCE.md`，不憑記憶寫；該檔未列者就寫規範名稱而不寫編號**——
編號錯誤比沒有編號嚴重。

**五、台灣現況**（`REFERENCE.md` 第六節）。台灣現為零商轉反應器，核三 2 號機
2025-05-17 執照屆期停機；核管法 2025 年 5 月修正將運轉年限上限延至 60 年；
核三重啟公投 2025-08-23 同意多於不同意但未達 25% 門檻。
**寫作時嚴格區分「法律可能性」與「實際運轉狀態」**——兩者目前並存且方向相反。

## 已知不可用的來源

`SOURCES.md` 文末有完整清單與實測結果。最需要注意的是：

**NRC（nrc.gov）全站對本系統回 403**，HTML 與 RSS、curl 與 WebFetch 都一樣。
美國管制動態一律經 ANS Nuclear Newswire 等第三方取得，
依規範**不得標 A 級**，並須在待查核註明「本報未取得 NRC 原文」。

韓聯社與 Korea Herald 為 JS 渲染，靜態抓取取不到標題；台電的「核能發電」頁
只有導覽選單，機組狀態改用開放資料 JSON（判讀規則見 `SOURCES.md`）。

## 設計取捨

**為什麼是 Markdown 而非 HTML**：內容與呈現分離。改版面不必碰內容，改內容不必碰程式。

**為什麼由母站 index.html 衍生而非重寫**：前端的卡片化、來源等級標籤、
事實與判讀分段等邏輯全部是通用的——它依渲染後的 H2／H3 建構，不綁定特定主題。
只換了品牌字串、預設配色，以及把「前一日市場」的漲跌上色改為機組狀態的異動標示。

**為什麼機組狀態表取代市場表**：核能晨報的讀者要先知道「哪些機組現在是什麼狀態」，
就像財經讀者要先看價格。台灣機組即使無異動也固定列出。

**為什麼要回接研究框架**：本站讀者為研究者。每則寫到相關主題時直接指向具體規範編號、
遇已查證的研究缺口時點名、國際案例加一句「對台灣的意義」。
這三項是研究框架的回接，不是立場的夾帶，均須落在可觀察的事實與後果上。
